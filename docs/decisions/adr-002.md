# ADR-002: Mock Mode para Desenvolvimento

## Status
**Aceita** — Ativo em produção.

## Contexto
O desenvolvimento precisa funcionar sem conexão com Supabase (offline, demos, testes rápidos). Além disso, novos desenvolvedores precisam conseguir rodar o app imediatamente sem configurar Supabase.

## Decisão
Implementar `mockDb` em `src/lib/supabase.ts` que replica a API do Supabase usando `localStorage`.

## Implementação

### Detecção Automática
```typescript
const isMockMode = !url || url.includes('placeholder');
```

### API mockDb
```typescript
mockDb.get(table)     // → { data: [...] }
mockDb.set(table, data) // Persiste no localStorage
```

### Coleções Suportadas
- `monitorias`, `users`, `teams`, `forms`, `quality_configs`
- `access_requests`, `user_teams`, `dissatisfaction_fields`
- `business_hours`, `holidays`

### Persistência
- Prefixo `qualitrack_mock_` em todas as chaves do localStorage
- Sessão mock persistida em `qualitrack_session` (sobrevive a F5 e fechamento de aba)
- Última atividade em `qualitrack_last_activity`
- Presença online em `qualitrack_active_sessions` (heartbeat 10s, timeout 25s)

### Seed Data
- 2 equipes padrão: Alpha (`team-alpha`), Beta (`team-beta`)
- `user_teams` auto-seeded para usuários suporte/gestor_suporte no init
- Usuário padrão: `qualidade@webposto.com.br` / `123456` (admin)
- Outros perfis são usuários temporários e serão removidos na publicação

### Autenticação Mock
- Compara email/senha diretamente no localStorage
- `enrichUserWithTeamIds()` aplica em modo mock também
- Sessão: `{userId, sessionStartedAt, sessionExpiresAt}`

### Responsabilidade do Desenvolvedor
Todo CRUD novo precisa suportar Mock Mode:
- Se adicionar query Supabase, adicione a persistência equivalente em `localStorage` via `mockDb`
- Se adicionar tabela, adicione seed data no init do mockDb
- Se adicionar filtro no dashboard, aplique em ambos os modos

## Consequências
- ✅ Desenvolvimento sem dependência de serviço externo
- ✅ Demos instantâneas sem setup
- ✅ Onboarding rápido para novos devs
- ⚠️ Duplicação de lógica CRUD (mock vs real)
- ⚠️ Mock não replica RLS, triggers ou Edge Functions
- ⚠️ Possibilidade de divergência de comportamento mock/prod
